ROSA Knee Surgical Planning System (Clinical Atlas)

Complete Technical Architecture, Clinical Workflow & Viva Examination Guide
Auditable AI-to-Mesh & 8-Step iKA Planning Platform

1. Executive Summary & Project Goal

The ROSA Knee Project (Clinical Atlas) is a full-stack medical engineering research prototype for Robotic-Assisted Total Knee Arthroplasty (TKA).

  • Patient Ingestion: Captures patient clinical records, MRN, and radiograph/CT metadata.
  • AI-Assisted Segmentation: Multi-class volumetric bone segmentation (Femur, Tibia, Patella, Fibula).
  • 3D Anatomical Reconstruction: Coordinate-preserving 3D surface mesh generation in millimetric LPS physical space with non-shrinking Taubin smoothing.
  • Deterministic iKA Planning: Closed-form 8-step Inverse Kinematic Alignment mathematical planning based on the 2025 ROSA clinical trial protocol (Eijking et al. 2025, NCT05685693).
  • Cryptographic Audit Ledger & Hard Export Gate: SHA-256 manifest sealing that blocks unverified cut instructions from reaching surgical robotics consoles.

2. Clinical Problem & Significance

  • Traditional TKA: Relies on 2D radiographs and manual cutting blocks, causing up to 20% patient dissatisfaction due to ligament tension imbalance.
  • Commercial Surgical Robotics (e.g., ROSA, Mako): Proprietary, expensive "black boxes" where planning mathematics and intermediate 3D anatomical meshes cannot be inspected.
  • Clinical Atlas Solution: An auditable, open-architecture surgical platform with deterministic kinematic alignment, real-time 3D WebGL visualization, and cryptographic safety verification.

9. Top 20 Viva Questions & Short Answers

1. What is the main objective of your project?
To provide an open, auditable clinical platform for AI knee segmentation, 3D bone reconstruction, and robotic TKA surgical planning.
2. What is TKA?
Total Knee Arthroplasty — a surgical procedure where damaged knee bone and cartilage are replaced with artificial implants.
3. What is Inverse Kinematic Alignment (iKA)?
An advanced surgical technique that restores the patient's individual, natural knee anatomy and ligament balance rather than forcing everyone into a standardized straight line.
4. Why did you use React for the frontend?
For its modular component architecture, dynamic state rendering, and seamless integration with WebGL 3D libraries.
5. Why did you use FastAPI for the backend?
Because Python is the standard for scientific computing, 3D geometric processing, and machine learning libraries (NumPy, PyTorch, VTK).
6. How does the 3D viewer work in the browser?
It uses Three.js to render 3D meshes (femur, tibia, patella) and virtual resection planes directly on an HTML5 canvas via WebGL.
7. What is the purpose of Zustand?
It is a lightweight state management store that shares data like selected patient, 3D camera presets, and bone visibility across different pages.
8. How do the frontend and backend communicate?
Through RESTful API calls using standard HTTP methods (GET, POST, PUT, DELETE) exchanging JSON payloads.
9. What is CORS and why is it needed?
Cross-Origin Resource Sharing. It allows our React frontend running on port 3000 to securely make API requests to our FastAPI backend running on port 8000.
10. What database are you using?
SQLite managed through SQLAlchemy ORM, which can be swapped to PostgreSQL in production via environment configuration.
11. What bones are segmented in the knee?
Femur (thigh bone), Tibia (shin bone), Patella (kneecap), and Fibula.
12. What is a Dice Similarity Coefficient?
A statistical metric (0 to 1) used in medical imaging to measure the overlap accuracy between AI-predicted segmentation and ground truth manual annotation (>0.95 is excellent).
13. What is Taubin smoothing?
A two-step geometric mesh smoothing algorithm that removes surface noise from reconstructed 3D bones without shrinking their volume.
14. What is the Hard Export Gate in your project?
A safety mechanism in the backend that blocks exporting 3D STL files or robotic cutting instructions until an authorized surgeon cryptographically signs off on the plan.
15. What is the purpose of the SHA-256 cryptographic seal?
It generates an immutable hash combining image data, 3D mesh data, surgeon ID, and timestamp to prevent tampering with surgical plans.
16. What is the 2D CT viewer doing in ImagingViewer.jsx?
It renders cross-sectional CT slices across Axial, Coronal, and Sagittal planes with window/level contrast adjustment controls.
17. What are PROMs?
Patient-Reported Outcome Measures (like the Oxford Knee Score) used to track patient recovery and joint function post-surgery.
18. How do you handle file uploads in the backend?
Files are received via multipart form-data, validated for size/type, hashed with SHA-256, and stored in the uploads/ directory.
19. How is the project tested?
Using Pytest, covering API endpoints, mathematical iKA planning logic, mesh generation, and cryptographic audit gates.
20. What is the difference between what is implemented and what is a placeholder?
The entire frontend, 3D viewer, REST API, mathematical iKA equations, mesh smoothing engine, audit ledger, and test suite are fully implemented. The live GPU deep-learning inference loop is cleanly structured as a dispatch hook ready for trained model weights.
